# Exemplo preenchido — Aurora Sistemas (empresa fictícia)

Este é um recorte de como a documentação fica **depois** de preenchida, para uma empresa fictícia (Aurora Sistemas, que desenvolve um portal de clientes). Note que a stack dela (React + NestJS + PostgreSQL) é diferente do exemplo default do template — **a stack é uma variável do método, não parte dele**.

Arquivos incluídos no recorte:

| Arquivo | Mostra |
|---------|--------|
| `DocumentacaoPadrao.md` | Hub preenchido: catálogo com 3 sistemas, índice, regra anti-confusão real |
| `ESTADO-ATUAL.md` | Status vivo curto com pendências reais |
| `sistemas/hub-clientes.md` | Ficha de sistema completa, com "O que NÃO é este sistema" |
| `decisoes/001-fila-de-emails.md` | ADR real: por que e-mails vão para fila e não envio direto |

Numa implantação real, existiriam também os `modulos/` preenchidos, `referencia/`, `progresso/` — omitidos aqui por brevidade (a estrutura completa está em `template/`).
